Programação Web Avançada

  1. O que são operações de “Commit” , “Push” e i “Pop” efetuadas num repositório?

    Resposta:

    • Commit: Guardar as alterações feitas localmente no repositório, acompanhadas de uma mensagem que descreve as alterações.
    • Push: Enviar os commits locais para um repositório remoto.
    • Pop: No Git, o comando git stash pop aplica as alterações guardadas temporariamente e remove-as da lista do stash, se a aplicação for bem-sucedida.

  2. Quais são as vantagens de usar branches num repositório Git?

    Resposta: Os branches permitem desenvolver funcionalidades ou corrigir erros de forma isolada, sem afetar a versão estável (main). Facilitam o trabalho em paralelo entre várias pessoas, permitem experimentar sem risco e só se junta o trabalho ao main quando está pronto e testado.

  3. Nos merges de conteúdos resultantes de um “Pop” podem resultar conflitos. Em que consistem e como podem ser resolvidos esses conflitos?

    Resposta: Um conflito acontece quando o Git não consegue juntar automaticamente duas alterações, normalmente porque as mesmas linhas do mesmo ficheiro foram alteradas de forma diferente nos dois lados. Resolve-se abrindo o ficheiro, escolhendo ou combinando o conteúdo final, apagando os marcadores de conflito e executando depois git add e git commit, quando aplicável.

  4. “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais são as diferenças entre eles?

    Resposta: O clone copia um repositório remoto para o computador e configura uma ligação ao repositório original. O fork cria uma cópia do repositório na conta do GitHub, permitindo fazer alterações sem precisar de permissões de escrita no original e, posteriormente, propor essas alterações através de um pull request.
